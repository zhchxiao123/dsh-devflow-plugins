# @zhchxiao123/dsh-devflow-jev

[English](README.md) | 中文

面向 Devflow 项目的类型化判断。插件注册模型工具，将不可变评估存储在 `.devflow/judgements` 下，仅在显式接受提案时创建卡片，并提供原生审查侧边栏。

## 工具

- `devflow_assess`：评估新需求（`target: "request"`、title/body）或已有卡片（`target: "card"`、id/assessmentKind）。不会创建卡片或改变阶段。
- `devflow_decide_judgement`：通过 id/action 接受或拒绝提案；接受操作幂等创建提议的卡片。

通用 JEV 运行时提供共享入口：

- `jev_run`：使用 `source: "devflow-audit"` 和可选的 profile/maxCards 启动项目审计。
- `jev_list`：汇总已安装来源。可按 `devflow-audit`、`devflow-assessment` 或 `devflow-assistance` 筛选，添加 id 查看详情。
- `jev_control`：通过 source/id/action 恢复或取消审计及通用运行。

旧的评估、判断决定和审计工具名已取消注册；既有持久化记录和 Web 传输保持兼容。专用 `jev_triage` 工具仍独立存在。

JEV 失败记录为 `unavailable`，不会因此创建或移动卡片。

## 自动研发指引

Harness 支持系统提示词且 JEV 提供方已配置时，项目会话会收到与当前可见评估工具对应的 Devflow 指引。普通研发对话中，agent 可以评估实质性新需求或已有卡片版本，用户无需点名 JEV。通用证据审查与项目审计使用现有共享工具。指引不接受提案、不重复建卡、不推进阶段，也不替代 required validators；原有授权及门禁继续适用。凭据与工具可见性按会话检查，卸载插件会移除指引。

这是给 Harness agent 的指引。组装后的提示词只能证明指引存在；自然语言任务中是否出现合理调用和有证据支持的决策，需要单独验证。

## 自动辅助

自动辅助独立于提示词指引。默认模式为 `observe`：在符合条件的研发检查点记录有预算限制的判断，不投递建议，也不延长 agent 回合。将 `assistance.mode` 改为 `assist` 后，通过当前 Harness agent 投递建议；`off` 关闭这些自动钩子，显式工具和指引仍然可用。

```yaml
- name: '@zhchxiao123/dsh-devflow-jev'
  config:
    assistance:
      mode: observe
      timeoutMs: 5000
      maxCallsPerTurn: 3
      maxSteersPerTurn: 1
      confidenceFloor: 0.75
      maxBytes: 24000
      maxFiles: 12
      maxFileBytes: 4000
      repeatThreshold: 2
```

以上为默认值。修改已有插件配置行，不要重复添加实例。观察器识别已支持的研发工具和事件，不会自动分类任意工具。它采集有界的 checkout 证据及实际工具结果，记录未覆盖范围，并检查凭据、取消、新鲜度、去重和预算。Harness agent 仍是执行者；自动辅助不能推进卡片或绕过验证。卡片归属不明确，或派发 worktree 的所有权未经验证时，仅保留会话级建议。

策略版本 3 保留模型原始行动及其被投递或低于门槛的原因，并从已提供需求及实际失败的工具结果中选择具体调查目标。该目标仍是未验证的建议，不是已确认缺陷。自然语言需求或只读 shell 命令本身不会触发远端判断；已完成的设计产物、本轮基线之后的实际改动、重复失败或完成检查点可在预算内触发。`maxCallsPerTurn` 至少为 2 时，中间检查点会保留最后一次调用给完成检查或重复失败。由 `observe` 切换为 `assist`，或恢复本地凭据配置后，可在剩余预算内重新评估未变化的证据。对于相同证据、事件、策略版本和提供方配置身份，已投递及投递结果不确定的建议不会重放。

实现涉及三个已有包：`devflow-jev` 负责自动辅助；`jev` 提供可选的 `configurationIdentity()` 元数据，供消费方使缓存失效；`jev-typesafe` 对提供方、模型、端点和凭据引用生成指纹，不包含凭据值。配置身份不证明提供方健康，也不能识别同一引用背后的密钥轮换。

取证限制在会话的规范化工作目录内，即使它只是大仓库的一个子目录，也不会扩展到相邻项目。本轮本地基线会从后续请求中排除未变化的旧脏文件；基线元数据不发送给 JEV。安全的大源码文件即使无法提供完整摘录，仍可提供有界 diff。隐藏、敏感、不安全和二进制内容继续被排除并显示缺口。稳定的遗漏项不会让其他未变化证据自动过期。枚举截断、元数据不可读或采集过程中的变化会阻止复用；元数据新鲜度不证明完整代码或测试覆盖。

记录保存在 `.devflow/judgements/assistance/`。使用 `jev_list source=devflow-assistance` 查询，添加 id 查看详情。该来源只读，不支持恢复或取消。现有 JEV 审查面板增加“自动辅助”筛选与详情，可按关联卡片编号、标题、会话编号或原因搜索；本版没有在 Devflow 卡片详情中嵌入时间线。

详情把“已观察、投递待确认、已投递、过期、取消、不可用、预算用尽”与观测结果分开展示。有行动价值的建议保持可见；无行动、过期等诊断记录默认折叠，仍可展开查阅。过期记录说明变化了哪些证据，不把旧建议当成当前行动；卡片归属不明时记录原因而不猜测关联。没有证据时保持“效果未知”。之后出现行动或检查通过，不代表建议导致了修复、被采纳或解决了问题。记录分开保留行动选择集中度（`actionConfidence`）与干预支持概率（`justifiedProbability`），两者都不证明结论正确。观察到后续行动或检查时，结果详情记录真实工具调用编号及可用的退出状态，不声称因果关系。界面显示任务版本、触发原因、建议、证据引用、缺口和耗时，不公开完整采集源码。提示词送达和确定性测试不能证明普遍提效；需要另做自然任务对照。

## 项目审计

审计会快照当前看板，跨阶段抽样卡片，并按 profile 选择检查项。方案、实现风险、测试影响、评审范围、发布准备和规格差异使用各自的类型化问题。证据包括 journal 派生的卡片、完整历史、已登记产物及父子卡摘要。产物读取限制在卡片目录，拒绝凭据路径与符号链接逃逸，并设置严格的字节预算。

运行存储在 `.devflow/judgements/audits/<run-id>/`。不可变清单固定卡片版本、证据摘要、问题版本和检查计划；可变状态在每次检查后提交。类型化调用使用领域无关的 `JevRunEngine`；本包提供 Devflow 证据、问题、发现和 UI 投影。Harness jobs 提供实时输出与取消，项目文件跨重启保留。失去 job 的 planned/running 运行变为 interrupted，仅在显式请求后恢复；已完成且身份未变化的检查不会重跑。

JEV 审查侧边栏把通用运行、Devflow 审计和单项评估汇总到项目级搜索视图。详情显示覆盖范围、待处理项、错误、问题结果、证据与后续行动。Devflow 审计抽样未完成卡片和登记产物，不扫描整个仓库；通用运行保留自己的对象和问题定义。审计不会创建卡片或移动阶段。需求提案在显式接受前展示拟创建任务。

“新建审查”支持提供证据的通用清单、Devflow 审计、新需求或已有任务评估。通用清单使用是/否问题；更丰富的多选或评分问题通过 `jev_run` 的完整运行定义提交。通用表单不采集仓库文件。工具与 Web 操作共享生命周期和评估服务。
