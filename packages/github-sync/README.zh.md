# GitHub 同步服务定义

[English](README.md) | 中文

`ctx.githubSync` 定义持久化内容服务，需加载 `@zhchxiao123/dsh-github-sync-local` 等提供者；独立于 Devflow 和活跃聊天。

消费者先使用 `registerConsumer` 注册独立游标，选择从头或当前位置开始；调用 `readChanges` 获取有序变化，处理成功后逐条按顺序 `acknowledge`。不能跳过尚未交付或确认的记录。`consumerState` 查询位置，`replay` 显式回放。

每条变化包含对应的历史快照版本。导出的 `consumePage` 是最小消费者示例，副作用处理器应以变化 ID 去重；处理后、确认前崩溃可能再次收到同一条变化。

`watch` 提供提交后的本进程唤醒通知，返回释放函数。通知不保证送达，消费者仍应轮询持久化变化。通知失败不回滚数据。

`sync` 在接收持久化后返回运行 ID 和接收时间。同一触发 ID 重试返回同一个运行；通过 `run` 查询排队、运行、等待、成功、部分完成、失败或取消。已接收不表示已完成。

外部内容仅作为不可信数据。本服务不评估 Issue、不创建开发任务、不执行讨论中的命令，也不写 GitHub。

取消确认使用原触发 ID 和 `cancelRequested: true`：取消已有运行，或先持久化一个已取消的回执再返回。同一触发的迟到普通投递不会启动工作。`resumeRun(runId, actor)` 显式恢复失败或部分完成的运行，保留原回执和已提交页面；订阅范围变化或后续内容提交会使检查点过期，此时需重新同步。`storage()` 可查询最后一次容量修改的调用者和时间。
