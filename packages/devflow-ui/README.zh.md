# @zhchxiao123/dsh-devflow-ui

[English](README.md) | 中文

Devflow 看板插件（浏览器半边）。看板有**两套面，且任一时刻只出现一套**：组合了 [`dsh-better-sidebar`](https://github.com/omdsh-dev/DSH-better-sidebar) 底座的部署里，它注册一个侧边栏页面（`dsh-devflow:board`，单实例，排在底座自带页面之后），头部控件根本不注册；其余部署里就是下面描述的悬浮控件。插件里由**同一处**根据底座是否在场做出选择，并在底座出现或离开时换掉已挂载的那一套——因此两者不可能同时出现。底座既不被 import 也不被声明为依赖：只在本地重述本插件调用的那一小片服务，一切经服务名交互，既满足 client bundle 纯度门，也让没有底座的部署行为逐字节不变。底座拒绝该页面（id 冲突）只告警，插件其余部分照常运行。

侧栏页面是占满整列高度、以阶段为中心的 Kanban。默认宽屏视图有七个有序 `DevStage` 列，每个列头报告占用该阶段的叶子工作项数量。`blocked` 仍是旁路，不会变成第八列：受阻卡片留在 `blockedFrom` 对应列并带明确警告；缺失来源阶段的异常数据进入显式兜底区，仍可打开。有子卡的顶层需求成为可折叠泳道标题，子卡只在真实阶段列出现一次；独立卡与父卡已离开活跃集的子卡共享“独立任务”泳道。已完成卡片降低视觉权重并默认限制数量，可按需展开。视图切换保留紧凑任务列表。窄面板用七阶段选择器一次展示一列，而不是把七列挤在一起；“开发中”有卡时优先进入该列，否则进入第一个非空阶段。没有当前阶段卡片的“独立任务”空壳会隐藏，父需求标题及其阶段分布则继续保留父子上下文。

页面头部承载标题（打开详情时是返回控件），工具栏报告工作区总数及进行中 / 受阻 / 已完成分布。加载中、已确定为空、首次读取失败是三种不同状态；失败可重试，已有成功数据时后台刷新失败则保留上一版看板。打开卡片继续使用既有详情表单——需求书、拆分关系、阶段产物、流转时间线默认展开且可折叠。底座能够持久化并重新发布页面设置时，该页面的设置卡上会出现“并列”开关：打开后看板在详情旁常驻，而不是被它取代。

侧栏页面呈现的是**它自己 scope 的**工作区，而不是应用当前摆在前面的那个会话：绑定按会话分桶，每个页面各取各的。它在成为展开面板里的可见 tab 时拉取；变更帧重取的是"可见页面正在关注的 scope"加上被选中会话——也就是 tab 角标与 `+` 菜单报告的那个——因此属于其他会话的后台 tab 不产生任何开销，而用户眼前的角标保持实时。被选中会话的看板另外在变更流每次建立时以及每次真实的选择变化时刷新。tab 角标报告上一次拉取得到的进行中卡片数（自身绝不发起请求），计数口径与页面统计头完全一致，且只在底座宣告 `badge` 能力时才提供。已知没有卡片的工作区把页面呈现为不可用而非隐藏；尚未拉取过的工作区保持可打开，因为打开正是拉取的触发点。

悬浮面是经 body portal 锚定在对话区右上角的控件（注册在会话头部工具 slot 上只为生命周期，渲染在其外，头部层叠上下文因此困不住它）。收起态是一颗显示进行中数量的胶囊（全部 `done` 时显示空闲文案）；展开态是紧凑只读列表。每行优先呈现状态、id、标题、本地化阶段、可选服务等级与产物数量、revision，不再重复七段流程条。列表保持一层：拆分需求领头、子卡缩进，父行报告 `k/n` 与子卡受阻状态，并可折叠；父卡缺席的子卡平铺为顶层，因此不会消失。点击行打开与侧栏相同的只读详情：需求 Markdown、关系、产物历史、持有者、命名流水线，以及按新到旧排列、带执行者、打回、审批、门禁裁决和接管事实的 journal 时间线。

看板数据经插件自持的读取面路由到达，由 [`dsh-devflow-web`](../../devflow/devflow-web/README.zh.md) 在应用同源位置提供，并以选中会话或页面自身会话为作用域。绑定层统一持有传输与可观察状态。`/devflow/ws` 下行 socket 宣告卡片变化；激活、连接建立、会话变化与变更帧都会触发重取。重连延时从两秒起翻倍、上限三十秒，并在下一次建立连接时复位。没有已取卡片时悬浮控件保持缺席；侧栏页面负责明确呈现加载、空和错误状态。

本插件不发出任何变更：卡片移动属于模型侧 devflow 工具与干预命令面，人工审批走现有的审批 composer——gates 插件把它们路由到 `ctx.approval`。

## Model Experience

None, as this package renders fetched board state for a human and touches no prompt, message, schema, stream, or tool result. The model's own view of the same cards stays with [`dsh-tool-devflow`](../../devflow/tool-devflow/README.zh.md).

#### KV Cache effect

None; the package never assembles or sends provider requests.

## Known Limitations and Deferred Work

- **行按设计只读** — PRD 的三操作面把语义移动留在聊天面、干预留在 `/devflow`；面板未来唯一的可操作元素是应答待审批项，如今经审批 composer 呈现。
- **没有 WIP 限制或阶段时长推断** — 列表响应不携带流程容量限制或阶段进入时间，因此 Kanban 只报告真实位置与数量，不虚构运营指标。
- **每帧变更全量重拉** — 每一帧都完整重拉看板；增量帧等看板大到需要时再来。
- **拆分标记只看得见 `blocked` 子卡** — 列表携带的是当前阶段而非历史，因此被打回到 `developing` 的子卡与正常走到那里的子卡无法区分；要在父行呈现打回，需要每张子卡的 journal。
- **折叠状态随挂载存在** — 折起一个需求是打开中面板的视图偏好而非存储项，面板重新挂载即复位。
- **非选中会话的页面持有过期角标** — 变更帧刷新的是被选中会话与可见页面关注的 scope；固定在另一个会话、既不可见也未被选中的页面会一直报告上一次的计数，直到它再次显示。
- **最新 Harness 已有真实侧栏组合基线** — 注册、互斥、拉取门、Kanban 投影、响应式阶段选择和详情联动继续由 jsdom 覆盖；打包后的 bundle 也已在 Harness `0.1.2-alpha.3` 与 `dsh-better-sidebar@0.18.0-alpha.0` 上启动，真实验证标签页容器、窄屏 Kanban、紧凑列表切换、卡片详情、产物和 journal 时间线。Harness `0.1.2-alpha.x` 必须选择底座的 `alpha` dist-tag；其稳定版 `0.17.x` 面向较早的 stable Harness。
