# @zhchxiao123/dsh-devflow-ui

[English](README.md) | 中文

Devflow 看板的浏览器端。它直接接入 DeepSeek Harness `0.1.5-rc.2` 自带的官方右侧栏：插件通过 `ctx.sidebarRightTabs` 注册 `devflow` 页签类型，并把页面主体挂载到带 key 的 `sidebar.right.pane.tab` 槽位。不再需要额外的侧栏插件，也不再提供悬浮降级入口。

页面是占满整列高度、以阶段为中心的 Kanban。宽屏视图包含七个有序 `DevStage` 列，每个列头报告该阶段的叶子工作项数量。`blocked` 仍是旁路，不会变成第八列：受阻卡保留在 `blockedFrom` 对应列并带警告样式；缺失来源阶段的异常数据进入兜底区，仍可打开。有子卡的顶层需求成为可折叠泳道，每张子卡只在自己的真实阶段出现一次；独立卡和父卡已经离开活跃集的子卡共享“独立任务”泳道。已完成卡片降低视觉权重并默认限制数量，可按需展开。视图开关仍可切换到紧凑列表。窄面板使用阶段选择器，不会把七列挤在一起。

工具栏显示总数、进行中、受阻和已完成数量，并选择看板讲的是哪一批卡片：进行中，还是档案。作用域与「看板／列表」是两个独立的轴，因此从任一视图都能进入档案——刚归档掉最后一张卡的人问的是「它去哪了」，不是「再给我看点别的」，而藏在某一个视图里的控件两个都答不上。工具栏是 chrome：活跃集为空时它依然在，而那正是通往档案的路最要紧的时候。加载中、确定为空、首次读取失败是三种不同状态；失败可以重试，已有成功数据时后台刷新失败会保留上一版看板。打开卡片后可以查看需求、拆分关系、阶段产物、持有者、命名流水线，以及按新到旧排列的 journal 时间线，各区块默认展开并可折叠。官方侧栏处于普通形态时，详情替换看板并提供返回操作；进入官方全屏形态后，看板与详情并排显示。归档卡片作为只读分组呈现，各自标注它是如何离开的——因为只有入档的卡片能回来，而那是 `/devflow` 上的决定。进入这个作用域才会拉取档案，离开即丢弃：这个集合是无界的，且相对看板是次要的。它的页在「加载更多」之后累积；变更帧到达时重新从第一页开始而不是续读，因为在两页之间被归档或恢复的卡片会让游标当初对应的集合发生位移。档案里没有阶段列——入档的工作不再流动，所以视图开关在那里被禁用并写明原因，而不是悄悄消失。

每一行还带着这张卡当下唯一可做的决定：已完成的卡提供归档，其余的卡提供放弃。两个都给，等于在每行放一个点下去必然被拒的按钮。工具栏把清扫放在它作用的那个计数旁边，计数为零时不渲染——一个经常无事可做的控件，会训练人不再看见它。

归档可逆，所以点击即提交。放弃不可逆，而且 store 拒绝空理由，所以它会打开一个提示框，理由写下之前确认按钮一直禁用：写下「为什么不做了」**就是**那次确认，在它之上再加一层「我知道」是仪式而非保护。恢复在这里刻意完全不提供。

操作按钮在每张卡自己的盒子里，是打开按钮的兄弟节点而不是子节点——button 套 button 是非法的，浏览器会把内层的点击算给外层。所以盒子是普通元素、打开按钮是它的子节点之一，操作因而读起来属于它所作用的那张卡，而不是浮在卡片下方。被拒的写会原样保留看板，并用它自己的措辞说明下一步；尤其 `revision-mismatch` 不是读者点错了，而是别的面动过这张卡，所以在告诉他之前看板已经在他脚下刷新过了。

每个页签读取其会话级槽位对应的工作区。插件按会话创建绑定，只在该页签主体可见时开始拉取；变更帧只刷新可见绑定，因此隐藏页签不会持续产生看板请求。只读 JSON 接口和 `/devflow/ws` 变更流由 [`@zhchxiao123/dsh-devflow-web`](../devflow-web/README.zh.md) 在应用同源位置提供。

本插件不发出任何变更。卡片流转属于模型侧 Devflow 工具与 `/devflow` 人工干预面；人工审批继续使用 Harness 的审批 composer。

## 运行时契约

Harness Web bundle 已经组合官方侧栏实现，`@deepseek-ai/dsh-client-ui-sidebar-right` 也已发布到 npm，但该 tarball 除 `@deepseek-ai/cordis` 外不声明任何依赖，而它的 `.d.ts` 引入了 `dsh-client-ui-dockkit` 与 `dsh-client-ui-layout/client`，二者又继续牵出 `dsh-brand`、`dsh-client-ui-theme`、`dsh-client-ui-settings` 以及 host 包 `dsh-host-webserver`。直接依赖它意味着要在本仓库固定整张依赖图，而在 `skipLibCheck` 下任何没固定到的成员都会静默塌成 `any`。因此 `sidebar-right.ts` 只重述当前使用到的公开注册表与槽位类型，并在每处声明上写明收窄了什么；实际运行行为全部由 Harness 提供。组件测试覆盖本插件基于这份重述所做的注册与 keyed 主体行为，但不能替代真实宿主组合测试，因此打包后的插件也已在真实 Harness `0.1.3-alpha.2` Web profile 中完成回归。在官方包为其类型补齐依赖声明之前，可移植的宿主自动组合 fixture 仍属于明确的发布例外。

## Model Experience

无。本包为用户呈现看板状态、并承载他们对「卡片在看板上的去留」所做的决定；它不接触 prompt、消息、schema、流或工具结果。模型对同一批卡片的视图属于 [`@zhchxiao123/dsh-devflow-tool`](../devflow-tool/README.zh.md)。

#### KV Cache effect

无；本包不会组装或发送模型请求。

## 已知限制与延后项

- **按设计只读** — 语义流转留在聊天工具里，运营干预留在 `/devflow`。
- **卡片打开按钮念出的是 id，不是标题** — 打开按钮带 `aria-label` 说明它打开什么详情，而 `aria-label` 会覆盖内容作为无障碍名称，因此视觉上看得见的标题不会被念出。修它是 `row.open` 的文案决定，不是结构问题。
- **没有 WIP 限制或阶段时长推断** — 列表不携带流程容量与阶段进入时间，因此看板只报告真实位置和数量，不虚构指标。
- **每个变更帧全量重拉** — 等看板规模确实需要时再增加增量协议。
- **拆分标记只看得到当前受阻子卡** — 要在父卡展示打回历史，需要读取每张子卡的 journal。
- **折叠状态、视图模式与作用域随挂载存在** — 它们是本地浏览偏好，页面重新挂载后复位。
- **官方侧栏包发布出来的类型不自洽** — 它的 tarball 没有声明自己 `.d.ts` 引入的任何包，因此本插件只重述所消费的那一片，安装目标必须是已经组合该服务与槽位的 Harness Web profile；插件刻意不再回退到第二套导航系统。
