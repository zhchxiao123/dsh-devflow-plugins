# Agent Note: Actionable-first 侧边栏与结局推导标签

Status: implemented

## Problem

判断侧边栏对用户说的是内部状态机词汇，且展示的大多数内容并不需要用户做任何事。想要自动化的用户把每张卡都读成一个要求；唯一真正提要求的队列——人工复核——依赖没人去点的点击，这也让校准导出一直缺标签。

## Decision

默认视图只回答一个问题：有没有需要处理的事？可行动 = 等待裁决的需求提案、结论为阻断的审计、可送达的辅助建议。其余一切——运行状态、已结束的审计、已定论或不可用的判断——折叠进既有的诊断区，kind 标签页或展开开关仍可到达。全部安静时用一句话说明。

标签来自结局而非点击。卡片到达 `done` 时，服务把它名下仍开放的卡级建议盖章为 `accepted`——该事件存在且语义精确。放弃（abandon）不发事件，运行时对这些记录不动手，由校准导出在导出时从 journal 的 `abandoned` 条目推导 `rejected` 一侧，这同时能标注本变更之前的历史记录。导出行携带 `labelSource`（`verdict` 或 `outcome`），校准可对两种来源分别加权。先行的人工裁决绝不被覆盖；需求提案继续等待显式决定——接受会创建任务卡，这一后果刻意保留一次点击的距离。

**归档被否决为拒绝信号**：store 只归档 `done` 卡片，`card-archived` 意味着已交付，把它映射为 `rejected` 会错标每一次已交付的归档。

## Alternatives considered

- 在放弃事件上做运行时拒绝盖章：事件不存在，上游造事件违反只依赖已发布表面的规则；改由导出读 journal。
- 删除被折叠的状态：它们是真实的，运维靠它们排障；折叠改变的是受众，不是记录。

## Consequences

健康项目的侧边栏接近空白，出现卡片就意味着需要一个决定。盖章天然静默失败——不可写的记录绝不干扰触发它的流转，已有测试证明。人工复核仍然可用但不再承重：标签从人们本来就在做的工作中积累。
