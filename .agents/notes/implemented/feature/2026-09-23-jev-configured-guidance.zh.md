# Agent Note: 普通研发中的 JEV 配置感知指引

Status: implemented

## Problem

提供判断工具并不能告诉 Harness agent 何时使用它们能改善研发任务。用户不应需要逐一指定工具调用，但无条件注入说明会宣传不可用的能力，并可能鼓励重复评估。

## Decision

JEV 服务提供与 provider 无关的异步配置状态，默认值为 unknown。TypeSafe 通过自己持有的 Harness 凭据服务解析配置的凭据引用。状态不泄露密钥或 provider 错误，也不请求远端验证身份。凭据已配置只说明可以注入指引，不证明 provider 能成功作答。

现有通用运行插件和 Devflow 插件各自负责可选的 system-prompt 内容。每个插件注册有序的空上下文，并在 system-prompt 组装 waterfall 中异步解析配置。它先调用后续处理，仅填充自己仍然存在的上下文，同时检查当前 agent 的工作区和工具可见性，不缓存 agent 状态。Harness 在 agent/pre-step 之前组装提示词，因此仅在该后续事件刷新会导致首次模型调用没有指引，并在凭据移除后多保留一步。服务、凭据或工具缺失时不注入对应说明；卸载插件会移除其内容。通用包保持独立于 Devflow。

指引覆盖证据采集、重要需求和设计中的不确定性、高风险实现变更，以及交付评审。应复用已有记录和未变化的证据；琐碎工作无需判断。运行状态、失败和未覆盖范围必须明确呈现。判断不能代替实际测试、接受提案或授权阶段迁移。

## Alternatives considered

- 静态 skill 或无条件提示词会在凭据或会话能力缺失时仍推荐工具。
- 消费方直接检查 TYPESAFE_API_KEY 会绕过凭据 provider，并把通用 JEV 绑定到单一供应商。
- 远端就绪探测增加延迟和潜在费用，也不能证明下一次判断一定成功。
- 强制评估钩子会形成工作流策略，而非对现有 Harness 执行器的使用指引。

## Consequences

该改动不增加包、模型工具或持久化数据格式。未实现配置状态的 provider 仍可正常工作，但不会启用自动指引。底层 provider 暴露轮换后的凭据值时，指引才会反映变化；修改外部 shell 变量不能改变运行中进程的环境。

组合测试验证实际组装的指引、凭据变化、可见性、隔离和卸载。这些测试证明提示词已送达，不能证明模型选择有价值调用的概率。自然调用质量及判断价值仍需通过新的自然语言研发任务验收。
