# Agent Note: JEV review workspace shows scope before verdict

Status: implemented

## Problem

仅列出内部评估类型、决策代码和置信度百分比，无法让开发者理解检查了什么、下一步该做什么。通用 JEV 运行也需要与 Devflow 审查和单项评估一起展示。如果不区分执行状态与检查发现，一次成功的 provider 调用就容易被误解为项目审查通过。

## Decision

原生 JEV 审查侧边栏是绑定当前会话的工作台，展示项目上下文，提供搜索，以及全部记录、通用审查、Devflow 审查和单项评估筛选。中文与英文标签说明记录的目的和状态。页面使用 Harness 主题变量，适应窄侧边栏与展开布局。

详情区分别展示执行状态、覆盖情况、发现和建议的下一步。检查清单包含所有计划项，包括尚无结果的检查。用户可以阅读类型化问题答案与已收集证据；自定义主体或模板没有内置标签时保留原始值。置信度描述的是一次判断，不代表审查进度，也不是项目正确性的证明。通用运行展示各项答案，不凭空生成总体结论。

HTTP 路由从当前会话解析工作区。`context` 返回项目名称、路径和通用运行能力是否可用；`run-list`、`run-read`、`run-resume` 和 `run-cancel` 操作该工作区的 `.jev` 记录。缺少通用运行服务时明确报错。读取支持持久化会话上下文，恢复与取消要求活动 agent。通用服务为工具和 HTTP 提供同一套生命周期方法，对同一运行串行处理控制操作，等待 job 绑定与 runner 启动，并保留 Harness 对取消操作的所有者检查。绑定失败会取消刚创建的 job。

创建表单支持 Devflow 卡片审查、拟议需求评估、已有任务评估与通用证据清单。工具与 HTTP 使用[共享入口服务](../architecture/2026-09-23-jev-shared-tool-entry-points.zh.md)。Devflow 审查读取已登记卡片证据；页面不会宣称具备仓库级源码采集或可执行通用模板目录。审查行为由[持久化项目审查记录](2026-09-22-jev-project-audits.zh.md)说明。

## Alternatives considered

**保留多个原始记录列表。** 这要求开发者自行从内部字段推断范围和含义，而且通用运行仍然难以发现。

**把成功执行视为审查通过。** 这混淆了 provider 可用性与答案内容，并掩盖待执行检查和缺失证据。

**另建浏览器专属 runner。** 共享通用服务可让工具与浏览器使用相同持久化记录和 Harness 所有者范围内的 job。

## Consequences

UI 让已有证据能够被理解和检查，同时保留不同领域的解释。展示判断不会把缺失证据变成验证，不会自动采集仓库文件，也不会推进 Devflow 卡片。生命周期锁只协调单个服务进程内的操作，不是分布式文件系统租约。

客户端行为测试覆盖列表和详情、待执行检查、明确的覆盖情况、创建表单和过期请求。真实 Loader/HTTP/jobs 组合测试覆盖通用运行发现、并发恢复、取消、恢复执行、工作区隔离、缺失服务和所有者拒绝。浏览器及本地安装后的运行验收与这些自动化检查分别记录。
